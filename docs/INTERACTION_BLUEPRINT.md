## 2. 产品定义

### 2.1 一句话定义

> **一个人可自然对话的机器人头**——你说话时它自然倾听(轻微点头、随节奏微晃),
> 它说话时配合语音自然动作,静默时平滑回中;全程安全可控,随时可急停。

### 2.2 核心基调

- 追求"**像人一样的自然动作**",不追求"内容响应";
- "听到'你好'就点头"这类**语义对应动作**经研究证明当前数据不可支撑(见
  `Project-Net/HANDOFF.md` §2 冻结结论),列为远期目标(§2.3 L4)。

### 2.3 交互形态分档(逐级演进)

| 档位 | 形态 | 说明 | 阶段 |
|---|---|---|---|
| **L1** | 轮转式(键盘代麦克风) | 你打文本 → 它"听"(生成倾听动作)→ 它回话(TTS 语音+说话动作)→ 回中 | **当前起点**,无麦克风也能全流程演示 |
| **L2** | 真对话 | 你开口说 → VAD 判定说完 → ASR → 它听(动作)→ 它回 → 回中 | 加麦克风+ASR |
| **L3** | 流式倾听 | 你说到一半它就开始轻微回应(边听边动) | 需增量动作生成,远期 |
| **L4** | 内容响应 | 听关键词点头、听疑问侧头 | **需新数据+新模型**,研究路线已冻结,最后做 |

## 3. 系统分层(最终架构)

### 3.1 四层架构

```
┌─────────────────────────────────────────────────────────────┐
│ ① 语音交互层(新增)                                            │
│    麦克风采集 → VAD(人声/静音判定)→ ASR(文本+词级时间戳)       │
│    TTS(机器人语音,多音色)→ 扬声器播放(与动作同步)              │
├─────────────────────────────────────────────────────────────┤
│ ② 对话管理层(新增)                                            │
│    行为状态机(speaking/listening/silent 切换)                 │
│    轮次管理(说完判定/停顿/打断/超时回中)                       │
│    回复生成(预置回复表 → 规则 → 将来接 LLM,接口预留)           │
├─────────────────────────────────────────────────────────────┤
│ ③ 动作生成层(Project-Net,现有,增量扩展)                       │
│    fragment 构建(音频+文本+词戳+role)                         │
│    v3 多候选模型(K=8,角色动作先验,GPU 推理 ~5ms)              │
│    候选选择策略 + 增量轨迹拼接(旋转合成/边界混合/Silent 回中)  │
│    → 输出自描述 V1 JSON                                       │
├─────────────────────────────────────────────────────────────┤
│ ④ 安全执行层(Project-Motor,现有,保持不动)                     │
│    V1 校验 → 坐标变换 → IK → S曲线重定时 → 100Hz 控制循环      │
│    → EtherCAT 电机 → 反馈监控/急停/watchdog/三把锁             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 职责铁律(不可逾越)

| 层 | 职责 | 不负责 |
|---|---|---|
| ① 语音层 | 采集/识别/合成/播放 | 动作生成、安全 |
| ② 对话层 | 判"该不该动/谁在说"、回复内容 | 动作生成、硬件 |
| ③ 动作层 | 只出动作轨迹(30fps 相对 RPY) | 关节限位/限速/坐标标定/硬件下发 |
| ④ 执行层 | 只安全执行轨迹 | 猜测输入语义(一切字段来自文件/配置) |

- **行为状态(说话/倾听/静默)≠ 硬件安全状态**,安全永远优先;
- 两端接口 = 自描述 V1 JSON(`format_version=1.0`),字段显式声明,零猜测。

## 4. 一次完整交互的数据流(L2 理想时序)

```
t=0.0s   用户开口 → VAD 检测 → 状态=LISTENING
         (L1: 用户按回车输入文本; 用户语音不播放,仅作为模型输入)
t=说毕   静音≥0.8s → VAD 判定说完
t+0.2s   ASR 出: 文本 + 词级时间戳
t+0.5s   动作生成(≈10ms):
           fragment(role=listener, 用户音频+文本+词戳)
           → v3 采样 K=8 → 策略选择 → 倾听动作段 [N1,3]
         拼接: [silent回中] + [listening段] + [思考停顿]
t+1.5s   回复生成: 回复表/规则/LLM → T_bot
t+1.6s   TTS 合成机器人语音(≈1s)+ whisper 对齐词戳
t+2.7s   动作生成:
           fragment(role=speaker, 机器人音频+文本+词戳)
           → 说话动作段 [N2,3]
         拼接: [speaking段] + [收尾回中] → 整条 V1 JSON
t+2.8s   ④ 执行: NeckTrajRun → dry-run 预检(重定时比例≈1)
t+2.9s   同步启动: aplay 机器人语音 + 动作执行
t+结束   动作播放完毕 → 状态=READY → 回中 → 等待下一轮
```

### 4.1 同步机制(关键)

- 动作时长 = 执行层**重定时后的计划时长**;语音时长 = 词戳末尾 + 0.5s 后垫;
- 靠"**选低能量候选**"(期望能量 ~2°/s 级)保证重定时比例 ≈ 1,动作与语音同步;
- 每轮生成后检查 `meta.max_frame_rate_deg_per_s`(V1 JSON 自带),超标自动换更安静候选;
- 实测参考:GPU 推理 K=8 仅 4-5ms、音频+特征 3-21ms、整段 4 段 mvp 生成 1.6s(含 Python 启动)。
  计算不是瓶颈,轮转式延迟预算 2-3s 可行。

## 5. 行为状态机(对话层,新增)

```
        ┌── 用户开始说话(VAD) ──┐
        ▼                        │
    LISTENING ──静音0.8s──▶ THINKING ──回复就绪──▶ SPEAKING
        ▲                                            │
        └──────────── 语音播放完+动作完 ◀─────────────┘
                              │
                              ▼
                          SILENT(回中)
                              │
                        ┌─────┴─────┐
                    下一轮开始     空闲保持(中位)
```

- 超时规则:任何状态卡住 >N 秒 → 安全回中;
- 物理急停随时打断一切(执行层已实现,不依赖本状态机);
- L1 阶段"用户开始说话"由键盘回车触发,"静音 0.8s"由回车即代表说完。

## 6. 能力与安全边界

### 6.1 能力边界

| 能力 | 状态 | 说明 |
|---|---|---|
| 自然动作(speaker/listener 平滑多样) | ✅ 已有 | v3 角色动作先验,已验证 |
| 音频调制动作幅度(弱节奏感) | ⚠️ 部分 | 研究结论:音频调制"动多少",不调制"何时动" |
| 精确节奏/语义响应 | ❌ 无 | 需新数据+新模型(L4) |
| 流式边听边动 | ❌ 无 | L3,远期 |

### 6.2 安全边界(继承执行层,不放松)

- 三把锁(`hardware_enabled` / `calib_confirmed` / `safety_confirmed`)控制实机;
- 急停可从任何状态触发;进程级 watchdog 心跳超时自动制动;
- 每轮实机前:`NeckTrajDryRun` 预检 + 低能量候选;实机时物理急停旁有人;
- 演示默认保守限速(25°/s),限速阶梯验证完成前不放开;
- 收工流程:`NeckDisable` + 关三把锁 + 物理断电。

## 7. 演进路径(S1-S5,每步可验收)

| 步骤 | 内容 | 新代码量 | 验收标准 |
|---|---|---|---|
| **S1** | 轮转式演示:键盘输入 → TTS 合成用户语音(不播放)→ 倾听动作 → 预置回复 → TTS 机器人语音 → 说话动作 → 回中 | Net 侧 2 个小脚本(`tts_align.py`、`make_round_events.py`,~140 行);两端现有代码**零改动** | 一轮完整跑通:听→停→说→回中,动作与语音同步 |
| **S2** | 麦克风+ASR 接入(替换用户音频来源),真对话 | 语音层 1 模块 | 真人对谈演示 |
| **S3** | 回复生成升级(规则 → LLM 可选) | 对话层小改 | 对话质量主观评估 |
| **S4** | 限速阶梯(+30% 逐级) + 连续运行 + A/B 候选策略 | 配置级 | 部署资格确认 |
| **S5** | 流式倾听动作(L3) | 增量拼接重构 | 自然度提升,边听边动 |
| L4 | 内容响应(新数据+新模型) | 研究项目 | 独立立项,不阻塞主线 |

> S1-S5 顺序实施、每步可验收;L3/L4 为远期,不阻塞主线。
