# SOEM 电机主站项目命令上手指南

## 1. 项目是做什么的

这是一个基于 SOEM 的 EtherCAT 主站示例程序。主站通过指定网卡连接 EtherCAT 从站，每个从站再通过 6 个通道控制电机：

- 通道 1、2、3：从站的 CAN1
- 通道 4、5、6：从站的 CAN2

程序启动后会进入交互式命令行。你输入电机命令后，命令先进入队列，再由约 1 ms 执行一次的通信线程发送给从站并读取反馈。

主要文件：

| 文件 | 作用 |
| --- | --- |
| `main.cpp` | 程序入口、网卡配置、注册交互命令 |
| `command.cpp/.h` | 解析命令参数并将命令放入发送队列 |
| `transmit.cpp/.h` | 初始化 EtherCAT、周期收发、从站恢复处理 |
| `motor_control.c/.h` | 将位置、速度、ID 等操作编码成电机 CAN 报文 |
| `config.h` | EtherCAT 过程数据结构，每个从站包含 6 路电机消息 |
| `queue.h` | 命令线程和通信线程之间的队列 |
| `thirdparty/soem` | SOEM EtherCAT 主站库 |
| `thirdparty/cpp-readline` | 交互命令行、历史记录和 Tab 补全 |

## 2. 先理解三个参数

几乎所有命令都围绕下面三个参数：

| 参数 | 含义 | 有效值 |
| --- | --- | --- |
| `SlaveId` | 程序中的从站数组索引 | 从 `0` 开始，最大为“识别到的从站数 - 1” |
| `PassAge` | 从站上的电机通道 | `1` 到 `6`；1~3 属于 CAN1，4~6 属于 CAN2 |
| `MotorId` | 电机 CAN ID | 建议使用 `1` 到 `2046`（`0x7FE`） |

例如，系统找到 2 个从站时：

- 第一个从站：`SlaveId = 0`
- 第二个从站：`SlaveId = 1`

> 注意：`SlaveId` 不是电机 ID，也不是 SOEM 内部从 1 开始的 `ec_slave[]` 下标。本项目命令统一使用从 0 开始的索引。

### 命令速查表

| 命令 | 用途 | 最简示例 |
| --- | --- | --- |
| `help` | 显示业务命令格式 | `help` |
| `MotorIdGet` | 读取电机 ID | `MotorIdGet 0` |
| `MotorIdSet` | 修改电机 ID | `MotorIdSet 0 1 2` |
| `MotorIdReset` | 将电机 ID 重置为 1 | `MotorIdReset 0` |
| `MotorAngleGet` | 读取电机位置 | `MotorAngleGet 0 1 1` |
| `MotorZeroSet` | 将当前位置设为零点 | `MotorZeroSet 0 1 1` |
| `MotorSpeedSet` | 设置目标速度 | `MotorSpeedSet 0 1 1 10 100 2` |
| `MotorPositionSet` | 设置目标位置 | `MotorPositionSet 0 1 1 90 50 100 2` |
| `MotorStop` | 发送制动停止命令 | `MotorStop 0 1 1` |
| `run` | 执行命令脚本 | `run commands.txt` |

上表中的示例均表示操作第一个从站（`SlaveId=0`）、通道 1、ID 为 1 的电机。详细参数和安全注意事项见第 6 节。

## 3. 编译前准备

### 3.1 安装依赖（Ubuntu/Debian）

```bash
sudo apt update
sudo apt install build-essential cmake libreadline-dev libboost-all-dev
```

如果项目是通过 Git 获取的，并且第三方目录为空，再执行：

```bash
git submodule update --init --recursive
```

### 3.2 找到连接 EtherCAT 的网卡

推荐使用：

```bash
ip -br link
```

也可以使用：

```bash
ifconfig
```

找到网线实际连接 EtherCAT 从站的有线网卡，例如 `enp4s0`、`eno1` 或 `eth0`。不要填写 `lo` 或无线网卡名。

### 3.3 修改源码中的网卡名

当前网卡名硬编码在 `main.cpp`：

```cpp
EtherCAT_Init((char *)"enp4s0");
```

把 `enp4s0` 改成第 3.2 节查到的网卡名，然后重新编译。

### 3.4 检查最大从站数

`transmit.h` 中默认为：

```cpp
#define SLAVE_NUMBER 4
```

它决定数组和队列最多容纳多少个从站。实际从站数不能大于该值；需要更多从站时，修改此值并重新编译。

## 4. 编译与运行

为避免旧 `build` 目录缓存了其他路径，建议使用一个新的构建目录：

```bash
cmake -S . -B build-local
cmake --build build-local -j"$(nproc)"
```

生成的程序为：

```text
build-local/master_stack_test
```

SOEM 使用原始网络套接字，通常需要 root 权限：

```bash
sudo ./build-local/master_stack_test
```

看到以下关键信息，才表示主站进入正常通信状态：

```text
[EtherCAT Init] N slaves found and configured.
[EtherCAT Init] Operational state reached for all slaves.
从站数量： N
>
```

如果出现 `No socket connection`，优先检查 root 权限和网卡名称；如果出现 `No slaves found`，检查从站供电、网线和拓扑。

## 5. 交互命令行的基本使用

- 输入命令后按 Enter 执行。
- 输入命令前几个字母后按 Tab，可以补全命令名。
- 上、下方向键可以查看历史命令。
- `>` 表示上一条命令正常返回；`!>` 表示上一条命令格式错误或执行函数返回错误。
- 命令名区分大小写，例如必须写 `MotorIdGet`，不能写 `motoridget`。
- 输入 `help` 查看业务命令格式。

## 6. 全部电机命令

### 6.1 `MotorIdGet`：读取电机 ID

格式：

```text
MotorIdGet <SlaveId>
```

示例，读取第一个从站 CAN1 上的电机 ID：

```text
MotorIdGet 0
```

该命令固定通过通道 1（CAN1）发送广播查询。若 CAN1 上同时连接多个会响应的电机，可能产生响应冲突，建议按电机手册和实际拓扑操作。

### 6.2 `MotorIdSet`：修改电机 ID

格式：

```text
MotorIdSet <SlaveId> <OldMotorId> <NewMotorId>
```

示例，将第一个从站上 ID 为 1 的电机改为 2：

```text
MotorIdSet 0 1 2
```

该命令固定使用通道 1（CAN1）。修改前应确认旧 ID 唯一，新 ID 没有被其他电机占用。

### 6.3 `MotorIdReset`：重置电机 ID

格式：

```text
MotorIdReset <SlaveId>
```

示例：

```text
MotorIdReset 0
```

该命令固定使用通道 1（CAN1），会发送 ID 重置报文，重置后的 ID 为 `1`。这是广播性质的配置操作；同一总线上有多台电机时，应先隔离不需要重置的电机，避免产生重复 ID。

### 6.4 `MotorAngleGet`：读取当前位置

格式：

```text
MotorAngleGet <SlaveId> <PassAge> <MotorId>
```

示例，读取第一个从站、通道 1、ID 为 1 的电机位置：

```text
MotorAngleGet 0 1 1
```

正常反馈中重点查看：

```text
motor id: 1
angle_actual_float: ...
```

### 6.5 `MotorZeroSet`：将当前位置设为零点

格式：

```text
MotorZeroSet <SlaveId> <PassAge> <MotorId>
```

示例：

```text
MotorZeroSet 0 1 1
```

执行前必须确认机械机构处于允许设零的位置。该命令会改变后续位置控制所使用的零点基准。

### 6.6 `MotorSpeedSet`：速度控制

格式：

```text
MotorSpeedSet <SlaveId> <PassAge> <MotorId> [Speed] [Current] [AckStatus]
```

前三个参数必填，后三个参数可依次省略：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `Speed` | `0` | 目标速度；源码接口说明范围为 -18000~18000 rpm |
| `Current` | `500` | 电流阈值，按 0.1 A/单位解释时 `500` 表示 50.0 A；最终以电机手册为准 |
| `AckStatus` | `2` | `0` 不返回，`1`~`3` 返回对应类型的反馈报文 |

示例：

```text
# 使用默认速度、电流和反馈方式，即目标速度为 0
MotorSpeedSet 0 1 1

# 目标速度 100 rpm，其余使用默认值
MotorSpeedSet 0 1 1 100

# 目标速度 -100 rpm，电流阈值 300，反馈类型 2
MotorSpeedSet 0 1 1 -100 300 2
```

建议第一次调试从低速度、小电流阈值开始，并保证机构具备急停和限位保护。

### 6.7 `MotorPositionSet`：位置控制

格式：

```text
MotorPositionSet <SlaveId> <PassAge> <MotorId> [Position] [Speed] [Current] [AckStatus]
```

前三个参数必填，后四个参数可依次省略：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `Position` | `0` | 目标位置，单位为度 |
| `Speed` | `50` | 位置运动速度；源码说明按 0.1 rpm/单位编码 |
| `Current` | `500` | 电流阈值；源码说明按 0.1 A/单位编码 |
| `AckStatus` | `2` | `0` 不返回，`1`~`3` 返回对应类型的反馈报文 |

示例：

```text
# 回到 0 度，使用默认速度、电流和反馈方式
MotorPositionSet 0 1 1

# 移动到 90 度，使用默认速度、电流和反馈方式
MotorPositionSet 0 1 1 90

# 移动到 -45 度，速度 100，电流阈值 300，反馈类型 2
MotorPositionSet 0 1 1 -45 100 300 2
```

位置命令使用的是设零后的角度基准。执行大角度动作前，先检查零点、方向、机械限位和允许速度。

### 6.8 `MotorStop`：制动停止

格式：

```text
MotorStop <SlaveId> <PassAge> <MotorId>
```

示例：

```text
MotorStop 0 1 1
```

当前实现发送“变量阻尼制动控制”报文，固定控制值为 `10`，并设置为不返回反馈。它不是整个 EtherCAT 系统的硬件急停，不能替代急停按钮、安全回路或驱动器 STO。

## 7. 控制台内置命令

这些命令由 `cpp-readline` 提供，项目的 `help` 输出没有列出它们。

### 7.1 `run`：批量执行命令文件

格式：

```text
run <脚本路径>
```

脚本示例 `commands.txt`：

```text
# 查询位置
MotorAngleGet 0 1 1
MotorPositionSet 0 1 1 10 50 300 2
MotorAngleGet 0 1 1
```

在程序中执行：

```text
run commands.txt
```

注意事项：

- 以 `#` 开头的行会被忽略。
- 当前脚本解析实现不适合包含空白行，请删除空白行。
- 某一行返回非 0 时，脚本会立即停止。
- 命令进入发送队列后即视为该行成功，不代表电机已经执行完成；脚本也没有等待运动完成的功能。

### 7.2 `quit` / `exit`：退出命令行

当前版本中，`quit` 和 `exit` 只会结束交互线程，但不会把通信线程的 `running` 标志设为 `false`，主程序会一直等待通信线程，因此不能完整退出进程。

实际停机建议：

1. 对正在运动的每台电机执行 `MotorStop`。
2. 确认机构停止。
3. 按 `Ctrl+C` 终止主站进程。
4. 按设备规定顺序断开使能或电源。

## 8. 推荐的首次操作流程

假设只有一个从站，电机连接在通道 1，电机 ID 为 1：

```text
# 1. 查询当前位置
MotorAngleGet 0 1 1

# 2. 下发零速度，确认通信和反馈
MotorSpeedSet 0 1 1 0 100 2

# 3. 低速试转
MotorSpeedSet 0 1 1 10 100 2

# 4. 停止
MotorStop 0 1 1

# 5. 再次查询位置
MotorAngleGet 0 1 1
```

首次调试不要直接使用 ID 重置、高速度、大角度位置或大电流阈值命令。

## 9. 常见问题

### 9.1 `No socket connection on ...`

可能原因：

- 没有使用 `sudo` 运行。
- `main.cpp` 中的网卡名写错。
- 修改网卡名后没有重新编译。

### 9.2 `No slaves found`

检查从站供电、EtherCAT 网线、网口选择和拓扑连接。普通以太网设备不能当作 EtherCAT 从站。

### 9.3 从站无法进入 OP 状态

查看日志中的 `State`、`StatusCode` 和错误字符串。通常需要检查从站 PDO 映射、过程数据大小、从站配置和设备状态。

### 9.4 命令提示 `Command format error`

参数数量不对。带默认值的可选参数必须从左到右填写，不能跳过中间参数。例如要填写 `AckStatus`，就必须同时填写 `Speed` 和 `Current`。

### 9.5 命令提示 `Device or parameter error`

检查：

- `SlaveId` 是否从 0 开始并小于已识别从站数。
- `PassAge` 是否为 1~6。
- `MotorId` 是否为 1~2046。
- EtherCAT 通信线程是否正在运行。

### 9.6 输入命令后没有反馈

- `AckStatus = 0` 时本来就不请求反馈。
- `MotorStop` 当前固定不请求反馈。
- 检查电机通信模式是否与问答模式命令匹配。
- 检查通道、MotorId、CAN1/CAN2 接线。
- 查看是否持续出现 `Bad WKC`，它表示 EtherCAT 过程数据通信异常。

## 10. 当前版本的重要限制

1. 网卡名硬编码在 `main.cpp`，不能通过启动参数选择。
2. 最大从站数硬编码为 `SLAVE_NUMBER = 4`。
3. 命令队列每个从站最多缓存 10 条；批量快速下发时可能等待。
4. `MotorSpeedSet`、`MotorIdGet/Set/Reset` 和 `MotorStop` 的边界检查不完整。输入错误的 `SlaveId` 或 `PassAge` 可能造成数组越界，所以必须由操作者严格保证参数合法。
5. `quit/exit` 不能完整停止通信线程，应按第 7.2 节停机。
6. 软件命令不构成功能安全措施，运动设备必须配置硬件急停、限位和驱动器安全功能。

掌握本项目时，建议先熟悉 `MotorAngleGet`、零速度 `MotorSpeedSet` 和 `MotorStop`，再进行设零、位置控制和 ID 配置。
